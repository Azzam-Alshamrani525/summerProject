Who it's for

Two needs, one bot

Want a summary

  • Students and teachers — judge a lecture before watching
  • Busy people — clear the watch-later list
  • Arabic or English — chosen per summary

Want monitoring

  • Busy watchers — never miss an upload
  • Older and younger — no app to learn, it's just Telegram
  • Arabic or English — saved per person
How it works

Three routes, one workflow

Summarize
a link
You send a link→ Page is fetched→ Groq writes 3 bullets→ Reply, in your language
Follow
a channel
You send a channel→ Confirm it→ Pick a language→ Saved to your list
Every
hour
Check each channel→ New upload?→ Summarize once per language→ Send to every follower

The first two start when you tap. The third starts on a clock — nobody has to be there.

What was hard

Four problems worth solving

Buttons opened a browser tab
Rebuilt on Telegram callback buttons. Taps never leave the chat.
The model apologized instead of summarizing
It can't browse. Added a fetch step — transcript, description, title.
It forgot which button you pressed
The choice is now remembered, so the link works however you send it.
Every follower cost a separate API call
Followers grouped by language. Five readers, one call, five messages.
Honest limits

What I'd fix next

Known limits

  • One API key pays for every user
  • Two people saving at the same moment can overwrite each other
  • Videos without captions get a weaker summary
  • Summaries aren’t cached — the same link costs twice

Next steps

  • Per-user usage limits
  • A database for config, to stop overwrites
  • Monitor news sites, not just YouTube
