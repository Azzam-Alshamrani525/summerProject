# Week 6 — Day 3: AI Workflows & Chaining Agents

## Task
Multiple LLM steps process data sequentially before producing a final output.

## Workflow
Schedule Trigger → RSS Read → Limit → Edit Fields → Groq #1 (summarize) → Groq #2 (reformat) → Telegram

- **Groq #1** — title → intro line + 3 bullet points
- **Groq #2** — reformats #1's output for Telegram (short, emoji, no markdown)
- **Telegram node** — combines: real title + link (pulled directly from Edit Fields, not AI-generated) + Groq #2's text

Confirmed working end-to-end on a real phone.

## Delivery channel
Switched WhatsApp → Telegram. CallMeBot (free WhatsApp API) was unreliable — bot number kept changing, no response after multiple tries, 24h retry wait per their own docs. Telegram Bot API is official, free, has a native n8n node.

## Bugs (in order hit)
1. **`Fixed` vs `Expression` mode** on JSON body — placeholders don't fill in unless Expression is selected. (Repeat of Day 2's bug.)
2. **Empty `content` field** — reasoning model (`openai/gpt-oss-20b`) spends tokens on `reasoning` before `content`. `max_tokens` too low = empty `content`. Fixed by raising `max_tokens` (300 → 800 → 1500 once prompts got longer). Check `finish_reason`: `"length"` = cut off, raise tokens.
3. **Broken JSON from multi-line AI output** — Groq #1's bullet points contain real line breaks, which broke the JSON body when inserted raw into Groq #2's prompt. Fixed with `{{ JSON.stringify($json.choices[0].message.content).slice(1, -1) }}` to auto-escape it.

## Design note
Link and title are pulled directly from the Edit Fields node (`$('Edit Fields').item.json.title/link`), not generated by the AI — avoids hallucinated/wrong links.
