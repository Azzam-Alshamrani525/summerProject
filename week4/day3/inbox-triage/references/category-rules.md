# Category Signal Rules

Detailed signals for telling categories apart, for the cases the top-level SKILL.md summary doesn't resolve on its own.

## Urgent vs. Needs Reply
The line is **time pressure**, not importance.
- Urgent: contains a stated deadline within ~48 hours ("by tomorrow," "EOD," "before the 3pm call"), or words like "blocked," "down," "broken," "urgent," "ASAP" attached to something the user is directly responsible for.
- Needs Reply: a direct question or request with no stated deadline. "Can you review this when you get a chance" is Needs Reply, not Urgent, even though it's directed at the user.

## Needs Reply vs. FYI
- Needs Reply requires the user to produce something back — an answer, a decision, an approval.
- FYI is closed-loop already — a status update, a confirmation, a "just so you know." If the user's silence wouldn't cause a problem, it's FYI.

## FYI vs. Can Wait
- FYI: informational and time-relevant now (e.g. "deploy went out today").
- Can Wait: informational or low-stakes but not time-relevant (e.g. "here's a doc for whenever you're free," a low-priority suggestion, a non-urgent heads-up about something weeks out).

## Can Wait vs. Noise
- Can Wait still came from a real person about a real (if low-stakes) topic.
- Noise is automated or mass-sent: newsletters, digest emails, system notifications, marketing. If unsubscribing wouldn't lose the user anything meaningful, it's Noise.

## Sender weight
A request from a manager, direct report, or client generally outranks the same request from an unrelated party — but only use this to break ties between adjacent categories (e.g. push a borderline Needs-Reply toward Urgent), never to invent urgency the content doesn't support.
